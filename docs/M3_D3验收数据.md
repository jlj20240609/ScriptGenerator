# M3 D3 结果语义判定 · 验收数据

生成时间：2026-09-11 17:59:36　模型：`glm-4.6v`　每例重复：1 次

## 这一层在做什么

本地 D2 只回答「预期的东西出现了没有」；D3 回答「没出现的话，是哪一类失败」。
两者输出**同构**（`{ok, kind, label, reason, source, ...}`），所以调用方不必
区分这次判定来自本地还是云端。

## 结果

| 路径 | 判对 | 说明 |
| --- | --- | --- |
| 本地文字预判 | 6/12 = 50% | 屏幕上写着现成的话，不花云端调用 |
| 云端 glm-4.6v（关掉预判） | 12/12 = 100% | 平均延迟 6562ms |
| 其中**含蓄用例**（本地必认不出） | 6/6 = 100% | 真实失败页往往不写「密码错误」这种现成的词 |

M0 的 D3 预研基线是 12 例纯文本 10/12（83%）。

**本表是「最新一次运行」的快照，模型有波动**：同一套用例、同一个模型，
上一次运行是 **11/12 = 92%**（唯一失手的是「凭据错/含蓄1」，模型答「不确定」）、
平均延迟 **3418ms**。所以引用时应取保守值 **92%**，延迟按 **3.4–6.6s** 的区间看，
而不是拿最好的一次当结论。两次运行合计 24 例中判对 23 例（96%），失手的那一例
模型是答「不确定」——**宁可不猜也不瞎猜**，属于可接受的保守，但要如实计入准确率。

## 云端用量（成本口径）

用户 2026-09-11 定的口径：**云端调用次数与延迟要计入验收指标**。

| 指标 | 本次实测 | 说明 |
| --- | --- | --- |
| 调用次数 | 12 次（失败 0） | 本次为测准确率把 12 例**全部**走了云端 |
| token 消耗 | 共 11383（输入 8760 / 输出 2623） | 平均 948.6 tokens/次 |
| 延迟 | 平均 6562ms/次 | 合计 78746ms |

**生产口径（本地优先开着）的预计调用次数：8/12 = 67%** —— 其余 4 例靠屏幕上现成的文字就判完了，一次云端调用都不花。

这个数字由「本地那一轮」实测得出（本地没判出的才会升级到云端），所以没有为了测它多花一次调用。

**币值换算**：这里只报 token 数，不写金额 —— 单价随模型与厂商牌价变动，写死一个数会在牌价调整后变成误导。按智谱当前牌价 × 上表 token 数即可算出。

## 架构边界（本层不越线）

- **云端只出语义标签，不出坐标**：判定结果里没有任何坐标字段，也有测试钉住
  （`engine/tests/test_outcome.py::ArchitectureBoundaryTest`）。
  坐标一律走本地三级定位，这是既定边界。
- **本地判得出时绝不调用云端**：D2 确认成功、或本地文字已说明原因时，
  一次网络请求都不发（有测试钉住，不是靠自觉）。
- **降级必须交给人**：云端未授权 / 超时 / 回复看不懂时，降级为
  「没出现 / 不确定」，绝不假装判出来了。

## 已知局限（如实记录）

- 用例集是**合成屏幕**：可复现、可回归，但覆盖面有限；真实产品的失败页
  文案千变万化，本表的数字是下限性质的参考，不是上线保证。
- 分类里没有「账号被锁」「需要二次验证」等类别——现有标签集只覆盖
  文档点名的几类；遇到集外情况模型会落到「不确定」，由人工接手。
