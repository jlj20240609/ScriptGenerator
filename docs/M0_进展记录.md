## 6.5 W2④ Electron↔Python IPC 原型（冒烟通过，2026-09-08）
- 产物：`smoke/electron_proto/`（主进程/预加载/覆盖层/渲染层）+ `smoke/m0_ipc_engine.py`（JSON-line 引擎桩）
- 链路：全屏透明选区覆盖层（Electron，DPI=DIP）→ 拖框（DIP）→ ×scaleFactor(1.25) 转物理像素 →
  JSON-line IPC → Python 引擎 mss 截图 + RapidOCR 定位 → 回传物理中心 → ÷1.25 画回覆盖层
- 自洽链路自动验证（全屏定位真值 C → 构造 60×60 搜索框 → 区域内二次定位）：
  - **坐标偏差 1.0px（125% DPI，无错位）**
  - **往返延迟：常驻引擎稳态 452ms（<1s 达标）；首次调用含模型加载 ~3.8s**
  - scaleFactor=1.25 与引擎物理坐标换算正确
- 150% DPI 复测：需临时切换系统缩放后重跑（`M0_AUTOTEST=1 npm start`）；公式与 scaleFactor 无关，预计同样成立
- OCR 区域限定是往返 <1s 的关键（全屏 OCR 10s+ 不可行 → 架构确认：小区域/缓存策略）

## 3. 判定口径（Spike）

- 每轮：随机移动窗口（可开关）→ 页面模板匹配（得分 ≥0.72 且回退到真值偏差）→
  部件三级定位（①UIA 树 ②OCR文本/模板相似度（邻域条带）③页面内坐标）→
  点击点文字校验通过且与真值偏差 ≤12px 才发送真实点击 → 全过 = HIT。
- 页面真值 = 程序移动窗口后已知的窗口矩形（内容整体平移），部件真值 = 采集时部件中心 + 位移 →
  定位偏差可精确量化，无需外部 oracle。
- 安全闸：校验不过一律不点（避免误点用户界面），记 `no_click_guard`。

## 4. 关键发现（草稿，待归入正式文档/变更记录）

### 4.1 OCR 性能（重要，影响架构决策）
- RapidOCR 3.8.1（本机 Python 3.14）：det 极快（<5ms 小图），**rec 阶段 ~130–160ms/行**，
  页面级 1280×800 ~49 行 ≈ 10–15s；150×44 小块 ≈ 0.5–1.5s（官方 ORT 下）。
- onnxruntime-directml 轮子的 CPU 执行比官方 onnxruntime（CPU）慢约 1.8–2×；
  本机无可用 GPU（DML 实际走 CPU），rec_batch_num 调大无效。
- 结论草稿：M1 引擎默认用官方 onnxruntime(CPU)；**页面级 OCR 全量扫描无法满足单步 ≤500ms 目标**，
  定位策略必须：小邻域条带 OCR / 页面级文本索引缓存 / 模板匹配优先。

### 4.2 UIA 覆盖（首份，10 个窗口样本）
- msedge（网页）：284 节点 / 110 交互 / 105 有 Name → 覆盖良好（网页文本部件可走 UIA）。
- QQ.exe：8 节点、0 交互、0 Name → **无 a11y**（自绘）→ 印证"无 UIA 场景"真实存在。
- explorer/PowerShell/桌面：覆盖中等；SystemSettings/Radmin 等窗口树空。
- 结论草稿：UIA 覆盖率与应用类型强相关，宣传口径按"可 UIA 应用 ~100% 文本可查 / 自绘应用 0"分层。

### 4.3 三级定位实测（样本小，正在积累）
- web 三目标（dyn/erp/login 修 L1 后）每轮 HIT，部件偏差 **0–1px**，页面匹配 0.84–1.00。
- **Edge DOM UIA 矩形与物理屏幕存在 ~140px 恒定偏差** → 网页类 L1 坐标不可信，
  已在链路内对 UIA 候选做“距页面内坐标预估 ≤60px”过滤（弃用远点候选）→ 网页类实际走 L2。
  （根因待查：uiautomation 对 Chromium 的 BoundingRectangle 换算。）
- 动态内容页（每秒心跳变化）：整页模板得分稳定在 0.84+，不受影响。

### 4.4 DPI / 坐标一致性（部分验证）
- 本机 125% 缩放（物理 1920×1200；GetDpiForWindow=120）。
- 进程内 `SetProcessDpiAwareness(2)`（per-monitor v2）后：win32 窗口矩形（物理像素）与 mss
  截图坐标一致（模板匹配 dev=0–1px 的实证）。
- ④ 的 Electron 选区层 DPI 校验留待 W2 原型做。

### 4.5 本机环境限制（数据解读时注意）
- 用户工作桌面活跃（DSH GUI + IDE 等大窗口），后台进程抢前台受 Windows 前台锁限制 →
  已采用 TOPMOST 置顶 + 页面定位失败自动"再点一次"重试 + 点击前校验兜底。
- 本机部分窗口（Windows 11 新版记事本、资源管理器、计算器 UWP）在"移动窗口后立刻抓屏"场景
  出现渲染不可见/内容漂移（tk 普通 Win32 窗口无此问题；Edge 窗口无此问题）——怀疑与
  系统动画/合成时序、远程/虚拟化环境（Radmin VPN 常驻）有关；**桌面类/图标类的“移窗后定位”
  数据建议在目标应用空闲、或用户指定真实业务软件时补采**。

### 4.6 工具链数据点
- mss 抓屏 1920×1200 全屏 ~15–25ms；cv2 金字塔模板匹配整窗模板 ~500–700ms（5 尺度）。
- 模板匹配对"低纹理页面"（大块同色）会错位匹配（tk 页得分 0.74–0.82 时曾偏差 137px）→
  低纹理页的页面定位得分阈值/融合策略留 M2。
