# M2 计划（可靠性增强）

> 日期：2026-09-10｜上游口径：《项目开发过程文档》§3 M2、《项目分析文档》§M2（L1076 起）
> 起点：M1 已收口（引擎 E1–E8 + Electron UI + IPC 契约 + 零编程用户演示；离线 168/168 全绿）。
> 本文是 M2 的**待批准计划**，拍板后按 §3 的波次开工。

## 0. DoD 与量化口径

官方 DoD（过程文档 §3）：

1. 真实案例库（**≥5 个脚本 × 各 50 次运行**）**命中率 ≥90%**；
2. **跨机/换分辨率验证一次**；
3. **误报率记录在案**。

M2 把这三条落成可自动测量、可复现的口径（避免"感觉还行"）：

| 指标 | 定义（可执行） | 目标 |
|---|---|---|
| **无人工介入率**（主指标，即"命中率"） | 该轮 `run_done.status == ok` **且**全程没有出现任何 `confirm_request`（没走 L1 弹窗、没弹"提示我"、没触发人工兜底） | ≥ **90%** |
| 成功率（辅助） | 该轮 `run_done.status == ok`（允许期间弹过窗并继续） | ≥ 95% |
| **误报率** | "引擎报告找到了、但点错/判错"的轮次占比。检出方式：每个案例带**终态断言**（如登录案例必须出现"密码错误"），运行结束由引擎自查该断言；**报成功但断言不成立**即计一次误报 | ≤ **2%**，且逐条记录到案 |
| 单步定位耗时 | 模板路径中位数（沿用 M1 口径） | ≤ 500ms |
| 定位方式分布 | 每轮用到的 `method`（uia/ocr_text/tpl/tpl_ring/anchor/page_coord）计数 | 仅记录，用于调优 |

## 1. 现状基线（M2 的起点）

- **引擎**：页面（整窗模板 10 档 + 同源确认三档 + 纹理下限 → 静态锚）、部件（①UIA → ②文字多候选/整块模板/环带 → ③页内坐标）、点击安全闸三道、L1（重试 2 次 + 白话弹窗 4 选项）/L2（on_fail 四策略）、自动校准（E5）、AI 语义确认（E7）。
- **UI**：Electron 列表式编辑器 + 双截图选区 + 运行日志 + 保存/打开；`--autotest-demo` 是零编程用户流程的自动等价物（41.5s）。
- **真窗回归**：`live_regress.py` 覆盖 login/erp/dyn/erp_v2/dyn_feed（各 4 轮）——都是**单轮**演示级强度，还不是 M2 要求的 50 轮统计。
- **M0 实测留给 M2 的硬骨头**（《M0_进展记录》/分析文档 §M0）：
  - **强动态桌面客户端（bilibili 视频流 feed）整窗模板仅 3%** → 需要局部特征/语义定位；
  - UWP 窗口在本机是"渲染幽灵"（置顶成功但屏幕不渲染）→ 属环境限制，需物理机补测；
  - 整页 OCR ~10s+ → 部件定位必须继续走小区域条带；**页面文本索引缓存**从 M1 中段挂到现在；
  - 150% DPI 未在本机验证过（M1 登记项，M2 DoD 第 2 条要补）。

## 2. 工作包

### WP1 真实案例库 + 统计框架（DoD 核心，必做）

- **案例库**：≥5 个脚本，覆盖不同难度：① 登录（含故意输错→提示我）② ERP 查询（静态页 + UIA）③ 动态心跳页（已有 dyn）④ 强动态内容流（已有 dyn_feed）⑤ 真实桌面客户端（控制面板/或在场时的 bili）。
  每个案例 = `.sgscript.json` + **终态断言** + 运行参数（是否移窗、是否改缩放）。
- **跑批器**：`engine/scripts/bench.py` —— 逐案例跑 N 轮（默认 50），每轮前可注入扰动（移动窗口 / 改缩放 / 清空输入框 / 制造遮挡），收集：run_done、confirm_request 次数、`method` 分布、耗时、终态断言结果。
- **报告**：`engine/scripts/bench_report.md/json`（按案例汇总 + 总命中率 + 误报明细 + 耗时分布）。
- 验收：能一条命令跑完 ≥5×50 并产出报告；报告里每个不达标案例都能定位到具体轮次与原因。

### WP2 强动态页面定位（技术难点，M0 遗留）

- 现状：整窗模板失配 → 静态锚（dyn_feed 已闭环，dev=1px）。若**整页都在变**（bili feed），锚也可能找不到。
- 方案分两步（先便宜后复杂）：
  1. **多锚共识**：页面上采多个小锚（顶栏 + 侧栏 + 底栏），任一命中即可还原页面原点；多锚同时命中时取中位，抗局部变化；
  2. **局部特征兜底**：ORB/AKAZE + RANSAC 估计页面位置（仅在 1 失败时启用；成本与鲁棒性先用案例库量出来）。
- 产品侧兜底（已实证）：引导用户停在静态子页（M0 实测 100%）。
- 验收：案例库 ④⑤ 的命中率进入 ≥90%，或明确记录"该场景不达标 + 兜底话术"。

### WP3 相似度融合权重调优（官方范围）

- 有了 WP1 的数据后，对**文字/形状/环带/邻居**的偏好顺序、阈值（text_sim_min 0.75、tpl 0.70、ring 0.60、同源三档 0.82/0.80、far_limit）做**网格搜索**，以"无人工介入率 + 误报率"为目标函数。
- 产出：`docs/M2_融合参数表.md`（每个参数的取值依据 + 调优前后对比数据）。
- 注意：调优必须在**留出集**（另一批脚本/扰动）上复验，避免过拟合到 5 个案例。

### WP4 UI 树路径消歧（官方范围）

- 现状：同名多实例只按"离录点最近的"选（≤60px 才用），且整页容器盒会拒绝。
- 目标：录制时记下**树路径**（父链 + 序号/自动化 ID），运行时优先按路径命中；路径失配再退回"名字 + 距离"。
- 验收：构造"同名多实例"页面（两个"保存"、多层嵌套），路径消歧后 ①级命中率与正确率都提升（案例库记录）。

### WP5 页面内坐标降级完善（官方范围）

- 现状：③ 级只在非 `exists` 时参与，且安全闸可能拦下（用户已加"按记下来的位置点一次"的半自动降级）。
- 目标：把 ③ 变成"**坐标 + 局部复验**"——用环带/邻居在坐标附近做一次确认，通过则视为有效证据（而不是纯几何）；
- 与 WP3 一起调参；产出记录进 `docs/M2_融合参数表.md`。

### WP6 L3 显式条件完善 + 循环上限 + 错误提示/日志（官方范围）

- **L3**：用户主动写"如果看到 X → 提示我/停止/重试"（编辑器已支持条件 + on_fail，M2 补齐**错误处理模板**与**多分支体验**）。
- **循环次数上限**：`repeat N` 现在无上限（`until` 有 1000）；补 `repeat` 的软上限与提示，`forever` 明确"靠停止按钮"。
- **错误提示与日志**：定位失败时给出"最可能的原因 + 下一步建议"（例如"页面被别的窗口压着，先关掉它"），并把候选 top3 长期保留在日志里（M1 已加）。

### WP7 脚本导入/导出分享（官方范围）

- 导出：`.sgscript.json` 单文件分享（含内嵌图像 data-url）；可选"瘦身导出"（图像外链目录 + 清单）。
- 导入：兼容性检查（版本、字段、缺失图像），给出白话诊断（"这个脚本是更新版本存的"）。
- 验收：跨机导入后可直接运行（与 WP8 联动）。

### WP8 跨机/换分辨率验证（DoD 第 2 条，必做）

- 本机 125% DPI 已验证；**150% DPI 必测**（改显示缩放即可，不必第二台机器）；条件允许再用另一台机器/另一种分辨率跑一遍案例库的子集。
- 产出：`docs/M2_跨分辨率报告.md`（缩放 100/125/150 下的命中率与偏差）。

### WP9 UI 打磨（可选，按你排期）

- 循环"把已有步骤圈进循环"（你之前选择维持现状，列在这里备用）；
- `Ctrl+S` 保存、撤销/重做、运行前预览"要做什么"的清单；
- 原生弹窗按 `kind` 定制文案（notify / not_found / outcome_fail / ai_authorize 四种语气）。

## 4. 风险与依赖

| 风险 | 影响 | 对策 |
|---|---|---|
| 强动态客户端（bili feed）本身不适合像素定位 | 案例库命中率被拉低 | 产品侧引导停静态子页（M0 实证 100%）+ 局部特征兜底；必要时把该场景单列并明确话术 |
| UWP"渲染幽灵" | 该类案例无法在本机验证 | 物理机补测；本机不把 UWP 计入命中率分母 |
| 50 轮 × 5 案例的机时 | 每轮含 OCR/定位，耗时较长 | 跑批放后台、逐案例串行、支持 `--rounds` 抽样；报告分案例增量产出 |
| 参数调优过拟合到 5 个案例 | 数字好看但不泛化 | 留出集复验（WP3 备注） |
| 真实客户端窗口会占用你的电脑 | 打扰日常使用 | 跑批默认不碰真实客户端案例；需要时由你确认后再跑 |

## 5. 需要你拍板

1. **案例库的 5 个脚本**：是否按 §WP1 的 ①②③④⑤（其中 ⑤ 需要你在场时跑真实客户端）？还是要换成你实际工作里的脚本（更有价值，但需要你提供页面/站点）？
2. **波次顺序**：是否按 M2-1 → M2-4？还是先做你更在意的（例如先 WP8 跨分辨率、或先 WP9 UI 打磨）？
3. **命中率口径**：以"无人工介入率 ≥90%"为主指标是否认可？（比"成功率"严，更贴近"可靠"）
4. **跑批强度**：5×50 会占用较长时间与鼠标键盘（跑批期间不宜用电脑）；是否可以只在你在场/空闲时跑，或抽成 5×20 先看基线？
5. **UWP/真实客户端**：本机不纳入分母、只做物理机补测，是否认可？
