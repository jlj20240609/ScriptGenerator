# M2 计划（可靠性增强）

> 日期：2026-09-10｜上游口径：《项目开发过程文档》§3 M2、《项目分析文档》§M2（L1076 起）
> 起点：M1 已收口（引擎 E1–E8 + Electron UI + IPC 契约 + 零编程用户演示；离线 168/168 全绿）。
> 本文是 M2 的**待批准计划**，拍板后按 §3 的波次开工。

## 0. DoD 与量化口径

官方 DoD（过程文档 §3）：

1. 真实案例库（**≥5 个脚本 × 各 50 次运行**）**命中率 ≥90%**；
2. **跨机/换分辨率验证一次**；
3. **误报率记录在案**。

M2 把这三条落成可自动测量、可复现的口径（避免"感觉还行"）：

| 指标 | 定义（可执行） | 目标 |
|---|---|---|
| **无人工介入率**（主指标，即"命中率"） | 该轮 `run_done.status == ok` **且**全程没有出现任何 `confirm_request`（没走 L1 弹窗、没弹"提示我"、没触发人工兜底） | ≥ **90%** |
| 成功率（辅助） | 该轮 `run_done.status == ok`（允许期间弹过窗并继续） | ≥ 95% |
| **误报率** | "引擎报告找到了、但点错/判错"的轮次占比。检出方式：每个案例带**终态断言**（如登录案例必须出现"密码错误"），运行结束由引擎自查该断言；**报成功但断言不成立**即计一次误报 | ≤ **2%**，且逐条记录到案 |
| 单步定位耗时 | 模板路径中位数（沿用 M1 口径） | ≤ 500ms |
| 定位方式分布 | 每轮用到的 `method`（uia/ocr_text/tpl/tpl_ring/anchor/page_coord）计数 | 仅记录，用于调优 |

## 1. 现状基线（M2 的起点）

- **引擎**：页面（整窗模板 10 档 + 同源确认三档 + 纹理下限 → 静态锚）、部件（①UIA → ②文字多候选/整块模板/环带 → ③页内坐标）、点击安全闸三道、L1（重试 2 次 + 白话弹窗 4 选项）/L2（on_fail 四策略）、自动校准（E5）、AI 语义确认（E7）。
- **UI**：Electron 列表式编辑器 + 双截图选区 + 运行日志 + 保存/打开；`--autotest-demo` 是零编程用户流程的自动等价物（41.5s）。
- **真窗回归**：`live_regress.py` 覆盖 login/erp/dyn/erp_v2/dyn_feed（各 4 轮）——都是**单轮**演示级强度，还不是 M2 要求的 50 轮统计。
- **M0 实测留给 M2 的硬骨头**（《M0_进展记录》/分析文档 §M0）：
  - **强动态桌面客户端（bilibili 视频流 feed）整窗模板仅 3%** → 需要局部特征/语义定位；
  - UWP 窗口在本机是"渲染幽灵"（置顶成功但屏幕不渲染）→ 属环境限制，需物理机补测；
  - 整页 OCR ~10s+ → 部件定位必须继续走小区域条带；**页面文本索引缓存**从 M1 中段挂到现在；
  - 150% DPI 未在本机验证过（M1 登记项，M2 DoD 第 2 条要补）。

## 2. 工作包

### WP1 真实案例库 + 统计框架（DoD 核心，必做）

- **案例库**：≥5 个脚本，覆盖不同难度：① 登录（含故意输错→提示我）② ERP 查询（静态页 + UIA）③ 动态心跳页（已有 dyn）④ 强动态内容流（已有 dyn_feed）⑤ 真实桌面客户端（控制面板/或在场时的 bili）。
  每个案例 = `.sgscript.json` + **终态断言** + 运行参数（是否移窗、是否改缩放）。
- **跑批器**：`engine/scripts/bench.py` —— 逐案例跑 N 轮（默认 50），每轮前可注入扰动（移动窗口 / 改缩放 / 清空输入框 / 制造遮挡），收集：run_done、confirm_request 次数、`method` 分布、耗时、终态断言结果。
- **报告**：`engine/scripts/bench_report.md/json`（按案例汇总 + 总命中率 + 误报明细 + 耗时分布）。
- ✅ **跑批器健壮性（离线补强完成）**：跑批是几十分钟级任务，机时不能白花——
  - **每轮立刻落盘** `bench_raw.jsonl`（最多丢当前一轮），默认**续跑**（跳过已完成的
    (案例, 轮号)，`--fresh` 才重跑）；读回时容忍坏行/半行。
  - **单轮异常不中断整批**：整轮（含移窗/复位/终态断言）都在保护里，出问题记成该轮
    `status=error` 并继续。
  - `--max-total-min`：到点停止开新轮并立刻写报告（要临时用电脑时不用守着）。
  - 失败轮默认留一张 960px 缩略截图（`--no-shots` 可关），路径写进该轮与报告明细。
  - 汇总口径抽成 `summarize()`（报告与测试共用），修掉一个真 bug：**误报轮（报 ok、
    无人介入、断言不成立）原先不会出现在"未达标明细"里**——现在未达标 = 没干净通过
    或断言不成立；"无人工介入"仍按 DoD 口径计，两条指标各司其职。
  - 测试：`engine/tests/test_bench.py` 10 例（离线、不触屏）。
- 验收：能一条命令跑完 ≥5×50 并产出报告；报告里每个不达标案例都能定位到具体轮次与原因
  （轮号 + status + 人工交互类型 + 校准原因 + 截图）。

### WP2 强动态页面定位（技术难点，M0 遗留）——**第一步（多锚共识）离线部分已完成**

- 现状：整窗模板失配 → 静态锚（dyn_feed 已闭环，dev=1px）。若**整页都在变**（bili feed），锚也可能找不到。
- 方案分两步（先便宜后复杂）：
  1. ✅ **多锚共识**（离线部分已完成，见下）；
  2. 局部特征兜底：ORB/AKAZE + RANSAC 估计页面位置（仅在 1 失败时启用；成本与鲁棒性先用案例库量出来）
     ——**待 M2-1 跑批数据**：先看多锚共识把案例 ④⑤ 拉到多少，再决定要不要上局部特征。
- ✅ **录制端采多个分散锚**（`engine/calibrator.py`）：以前只录**一个**锚（部件行带），
  它误命中了没有任何东西能纠正。现在录 `ANCHOR_MAX=3` 个：主锚（部件行带，沿用 M1 几何）
  + 按 3 行 × 3 列铺开的窄横条带（顶栏/工具条/状态栏这类横带最稳），用"与已选锚垂直距离
  最远"贪心挑选把锚摊到顶/中/底。
  - 三条过滤：**纹理下限** `ANCHOR_MIN_STD=10`（纯色块在整屏搜索时会到处匹配）、
    **内容重复** `ANCHOR_DUP_SIM=0.97`（重复图案提供不了独立证据，还会一起"一致地错"）、
    **重叠上限** `ANCHOR_OVERLAP_MAX=0.35`（挤在一起的锚等于只有一个锚）。
  - 效率：**多个锚复用同一帧**复验（M1 是每个锚各抓一次帧，锚越多越慢）。
- ✅ **运行端多锚共识**（`engine/locator.py`）：M1 是"命中第一个锚就返回"；现在把所有锚的命中
  都收下来，各自独立还原页面原点与缩放，**互相一致**（原点 ≤10px、缩放差 ≤3%）才算数，
  一致组取**中位**（抗一个离群锚）——这正是多锚的价值：单个锚误命中时无法自查。
  - 已有 ≥2 个一致就**早停**（不必扫完剩下的锚），代价是"常见情况 2 次锚扫描"；
    锚路径只在整窗失配的动态页上走，静态页零成本。
  - 锚之间**矛盾**（判断不了谁对）→ 取分数最高者，但标 `disagree=True` 并按
    `anchor_disagree_penalty=0.85` 打折置信度：诚实降级，不假装可信（"宁可失败也不误点"）。
  - 只录了 1 个锚的老脚本 → 矩形/置信度与 M1 **逐字段一致**（`consensus=1`）。
  - 定位日志新增 `detail.anchors[]`（每个锚的分数/是否入组）与 `detail.anchor_consensus`
    （试了几个、命中几个、几人一致、是否矛盾）——失败时能直接看出"是锚没找到还是锚之间打架"。
- ✅ 测试：`AnchorConsensusTest` 6 例（一致组吃掉离群锚并取中位 / 单锚与 M1 一致 /
  矛盾取高分+打折 / 缩放不符不算一致 / 早停条件 / 无候选）+ `MultiAnchorLocateTest` 2 例
  （动态页两个锚共识还原原点 / 页面被挪到画布别处仍还原）+ `AnchorBandPickTest` 4 例
  （条带分散且在页内 / 纯色页不采锚 / 多锚只抓一帧 / 重叠候选被丢）。
- 已知盲点（记录在案）：多锚共识**防不了"整体错位到另一个同布局窗口/标签页"**——那时多个锚会
  一致地指向错误位置。这类错由窗口标题/进程校验（`window.find`）与整窗同源确认兜底，不靠锚。
- 验收：案例库 ④⑤ 的命中率进入 ≥90%，或明确记录"该场景不达标 + 兜底话术"（待 M2-1 数据）。

### WP4 UI 树路径消歧（官方范围）——**已完成（离线部分）**

- ✅ **UIA 遍历带树路径**：`uia_walk_find_text` 的每个命中新增 `path`（从窗口根到该控件的
  祖先名字链，取最近 3 层）与 `depth`；录制时写进 `target.uia.path`（`widget.capture`）。
- ✅ **定位①级改成"先认身份、再认距离"**：命中多个同名控件时，优先选
  **树路径后缀匹配层数多**或**自动化 ID 相同**的那个；**身份对得上就不再因为"离录点太远"
  而弃用本级**——这正好解掉 M1 记下的那个洞：Edge DOM 坐标偏差 ~140px 时 ①级只能弃用。
  身份对不上时行为与 M1 完全一致（仍按距离 ≤60px，太远弃用），老脚本不受影响。
- ✅ 测试：`UiaLevelTest` 新增 2 例（路径对得上但远 → 选它且 level=1；没记路径又太远 →
  不误用①级），连同既有 5 例共 7/7 通过。
- 待做（需要屏幕）：真机复核（Edge DOM 场景下 ①级是否真的从"弃用"变为"命中"）。

### WP5 页面内坐标降级完善（官方范围）——**已完成（离线部分）**

- ✅ ③ 级不再"纯几何"：采纳前用**邻居文字**在预测位置附近做一次局部复验（`_nearby_ok`）
  ——这是 ② 级用不到的信号，有增量价值；复验通过 → 置信度 0.5 → **0.6** 并标
  `verified=True/method=nearby`；不通过也仍然返回（它本就是兜底），但如实标 `verified=False`，
  定位日志与统计里能区分"验证过的坐标"和"纯猜坐标"。
- ✅ **实现中的一个判断修正**：最初还在 ③ 里加了"环带模板精修"，写测试时发现它与 ②c
  **冗余**（同一个匹配器、②c 的搜索窗更大），几乎不可能"②c 失败而 ③ 的环带成功"，
  于是删掉、只留邻居复验——避免无谓开销，也避免"看起来更聪明其实没生效"的代码。
- ✅ 测试：`PageCoordVerifyTest` 2/2（部件换样子但邻居还在 → 走③且 verified=True、
  置信度提升；部件邻居都没了 → 仍返回但 verified=False、置信度 0.5）。
- 待做（需要屏幕）：真机上核对 `verified` 标记与安全闸的配合（安全闸目前独立判定，不读该标记）。

### WP6 L3 显式条件完善 + 循环上限 + 错误提示/日志（官方范围）——**离线部分已完成**

- ✅ **新增「停止」动作**：L3 的"如果看到'用户名或密码错误' → 停止"此前**无法表达**
  （六动作里没有"停止"）。现在 `action="stop"`（不需要框目标）→ 引擎按"运行被停止"收尾，
  并在报告里写明原因；编辑器动作区新增「停止」按钮；`schema.ACTIONS` 同步。
- ✅ **条件跨页语义修正**：条件目标所属页面**还没出现**时，原先一律走"否则"——
  于是"如果**没看到**'登录成功' → 重复点登录"会走进"否则"，与用户意图正好相反。
  现在按条件语义决定："没看到"→ 走"就做"；"看到"→ 走"否则"。
- ✅ **固定次数循环软上限**：`RunConfig.repeat_max=1000`（与 `until_max` 对齐），
  超出则按上限执行并记一条"重复次数 N 超过上限，按 1000 次执行"，防手滑写大数跑飞。
- ✅ **失败提示给"下一步建议"**：L1 白话弹窗在"没找到"之后追加一句建议
  （页面被挡住 → 先关掉挡着的窗口；部件变样 → 重新点"截图目标"框一次；
  内容变了 → 可选用"记下来的位置点一次"）。
- ✅ 测试：`L3TemplatesTest`（三种典型用法：看到就停 / 没看到就重试 / 看到就提示我）
  + `LoopLimitTest`（超上限只跑上限次并留痕）。

待做（需要屏幕）：`repeat` 上限触发时在 UI 上的提示排版、错误提示在真机上的语气核对。

## 4. 风险与依赖

| 风险 | 影响 | 对策 |
|---|---|---|
| 强动态客户端（bili feed）本身不适合像素定位 | 案例库命中率被拉低 | 产品侧引导停静态子页（M0 实证 100%）+ 局部特征兜底；必要时把该场景单列并明确话术 |
| UWP"渲染幽灵" | 该类案例无法在本机验证 | 物理机补测；本机不把 UWP 计入命中率分母 |
| 50 轮 × 5 案例的机时 | 每轮含 OCR/定位，耗时较长 | 跑批放后台、逐案例串行、支持 `--rounds` 抽样；报告分案例增量产出 |
| 参数调优过拟合到 5 个案例 | 数字好看但不泛化 | 留出集复验（WP3 备注） |
| 真实客户端窗口会占用你的电脑 | 打扰日常使用 | 跑批默认不碰真实客户端案例；需要时由你确认后再跑 |
