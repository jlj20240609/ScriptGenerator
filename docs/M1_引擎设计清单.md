# M1 引擎设计清单（页面模板 + 静态锚 + 校验模式闭环）

> 版本：v0.1（2026-09-09）｜性质：M1 引擎开发用清单（规格权威 = 《项目分析文档》v0.31 §5.1/§7.3/§11；
> 本文档只做模块化拆解、接口与验收条目，不重复设计正文）
> 依据的端到端演示：ERP v1→v2 改版恢复（dev 5px）、bili 动态页静态锚恢复（dev 0px）
> —— 工具原型在 `smoke/m0_calib_demo.py`、`smoke/m0_calib_bili.py`，回归时可复用其场景。

## 1. 目标一句话

M1 引擎实现"**页面模板/静态锚定位 + 校验模式自校准**"闭环：正常执行零 AI、纯本地相似度定位；
首次执行与过程性错误时自动进入校验（AI 语义确认 → 自动重采集 → 写回前自检），连界面改版与
持续动态页面都能自动恢复运行。

## 2. 模块清单（engine/ 包结构建议）

| # | 模块 | 职责 | 关键接口（草案） | M0 smoke 映射 |
|---|---|---|---|---|
| E1 | `engine/capture.py` | 双截图采集：页面（整窗 + 可选静态锚）+ 部件；锚自动建议与跨帧静态性复验 | `capture_page(hwnd) -> PageSpec`；`capture_anchor(page) -> AnchorSpec`；`verify_static(img, hwnd, dt=2s, thr=0.85) -> bool` | m0lib.grab_window_content / page_of_window |
| E2 | `engine/locator.py` | 页面定位（整窗模板 0.8~1.25× → 静态锚）→ 锁定页面范围；部件三级（UI 树/相似度/页内坐标），**只在页面范围内** | `locate_page(screen, page_spec) -> {rect, method, conf}`；`locate_widget(page_rect, page_live, target) -> {box, method, conf}` | m0_trial.locate_page_live / locate_widget_chain |
| E3 | `engine/matcher.py` | 多尺度模板（金字塔）、OCR 文本条带、融合打分、消歧（含 text_similar 子串方向规则） | `match_template_multi(scr, tpl, scales=[0.8..1.25])`；`find_text_strip(area, needle)` | m0lib.find_template / find_text_ocr（迁移并修正后版本） |
| E4 | `engine/executor.py` | 解释执行 JSON 步骤（六动作/条件/循环/L1 重试）；产出定位日志 | `run_script(sgscript, sink) -> RunReport` | m0_trial.do_run 骨架 |
| E5 | `engine/calibrator.py` | **校验模式子流程**：AI 语义确认（双图，归一化建议）→ 圈区本地精定位 → 全量更新 Target（页面/锚/部件/语义）→ 写回前自检 → 低置信人工兜底 | `calibrate(target, screen, ai) -> {updated, ok}`；`selfcheck(target) -> bool` | m0_calib_demo / m0_calib_bili 合并收敛 |
| E6 | `engine/logger.py` | 定位/运行 JSONL 日志（不进脚本文件）；校验触发时按 step 调阅 | `log_loc(row)`；`tail(step_id, n)` | smoke/data/trials.jsonl 模式 |
| E7 | `engine/ai.py` | 云端 VLM 适配层（默认智谱 glm-4.6v）：语义确认 prompt 模板（归一化输出）、结果解析、鉴权/授权钩子 | `confirm_target(old_widget_img, screen, semantic) -> {ok, norm_xy, conf}` | m0_vlm_geo（prompt 与解析） |
| E8 | `engine/schema.py` | `.sgscript.json` v1.0 读写与校验（Target 全量字段，见 §4） | `load(path) / dump(sg)`；`validate(sg)` | m0lib.Target |

## 3. 运行闭环状态机（M1 实现规格）

```
[录制] capture: PageSpec(整窗+anchors?) + Widget(target 全量)
  → 脚本 JSON
[执行循环] 每步:
  locate_page（整窗模板 → 锚）→ 失败? → [校验入口]
  → 页面锁定 → locate_widget（页面范围内三级）→ 失败? → [校验入口]
  → 动作（点击/输入/…）→ L1 语义检查（页面状态异常?）→ 异常? → [校验入口]
  → L2 预期校验 → 结果性失败 → 走 on_fail（retry/notify/stop/skip，不触发校验）
[校验入口]（首次执行必进一次；后续仅过程性错误触发）
  E5: 调阅 logger.tail(step_id) → AI 语义确认（部件旧图+当前屏）
  → 圈区本地精定位 → 更新 Target 全量 → selfcheck（正常路径试定位）
  → 通过: 写回脚本并继续；失败/AI 低置信: 弹窗人工确认（白话"自动校准"）
```

## 4. Target / PageSpec 数据规格（写 JSON 前对齐 §11 v0.31）

```jsonc
"page": {
  "context": { "process": "msedge.exe", "title": "*库存*", "class": "Chrome_WidgetWin_1" },
  "image": "data:image/png;base64,...",       // 整窗/页面截图（模板）
  "size": [1275, 975],
  "rect_in_screen": [13, 13, 1288, 988],       // 录制时（参考，不用于运行时假设位置）
  "anchors": [                                  // 静态锚（可空/多个）
    { "image": "data:...", "rect_in_page": [293, 49, 356, 43], "stable_at": "2026-09-09T..." }
  ],
  "scale_range": [0.8, 1.25],
  "capture_meta": { "dpi": 120, "ts": "..." }
}
"widget": {  // 每次部件（含校验更新写回）
  "image": "data:...", "rect_in_page": [...], "center_in_page": [...],
  "text": "库存查询", "match": "auto", "semantic": "ERP 左侧菜单里的库存查询项",
  "uia": { "name": "...", "automation_id": "..." }   // 可选
}
```

- 校验更新原则：页面/锚/部件同批写回并 bump 脚本内部 `targets_rev`；写回前保留旧值（回滚位）。
- 定位日志（引擎 JSONL，**不入脚本**）：`{ts, step_id, method(page_tpl|anchor|uia|ocr|tpl|page_coord|ai), confidence, rect, dev_px?, screen_meta}`。

## 5. M1 引擎验收条目（对应本项目清单条目）

1. 六动作 × 条件 × 循环解释执行（Login/ERP 样例脚本）端到端跑通；
2. **页面定位**：整窗模板 0.8~1.25× 移窗/整页缩放命中；整窗失配时锚定位生效（bili 场景回归：dev ≤20px）；
3. **页面内约束**：部件搜索与点击永不越出页面范围（构造"页面外相似物"负例验证）；
4. **校验模式**：erp-v2 改版场景自动恢复（dev ≤20px，无人工）；bili 动态页锚恢复；低置信人工兜底路径可触发；
5. 首次执行自动进校验一次并写回（不改步骤语义，仅刷新 Target）；
6. 定位日志 JSONL 生成、按 step 调阅；结果性失败不触发校验（走 on_fail）；
7. 单步部件定位 ≤500ms（OCR 条带缓存策略，分析文档 §4.1 实测依据）；
8. `.sgscript.json` 读写/校验通过；术语检查：界面与日志无技术词泄漏。

## 7. 待 M1 启动时细化的开放点

1. 锚自动建议算法（录制期静态性检测：多帧 diff / 文字行密度）——M1 先做"人工框选锚 + 自动复验"，自动建议 M2；
2. AI 适配层默认智谱（本机已验证），授权/知情提示 UI 联调在 M1 中段；
3. 校验触发的人工弹窗（Electron UI 侧）交互细节——与引擎 IPC 契约同步（`calibrate.confirm` 方法入开发过程文档 §6.1 契约表）。
