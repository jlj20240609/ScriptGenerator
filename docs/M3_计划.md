## 0. 官方范围（原文摘录）

## 2. 工作包

### WP1 录制引擎（`engine/recorder.py`）——**核心，不依赖云端 AI**

- **事件监控**：用已有的 `pynput` 做全局钩子（鼠标点击 / 滚轮 / 键盘），拿到**真实坐标与按键**
  ——比文档里设想的"实时截屏差分检测点击位置"简单且可靠得多（差分只用来兜底，不作为主路径）。
- **动作推断**（把原始事件流切成"积木"）：
  - 单击 → `点一下`；短时间内两次 → `点两下`
  - 连续字符按键 → **聚合成一次 `输入文字`**（关键：不能一个字一个积木）
  - 组合键（Ctrl/Alt/Win/Shift + X）→ `按快捷键`
  - 两次操作间隔 > 阈值（默认 1.2s）→ 自动插入 `等一下`（文档明确要求）
  - 功能键（Enter/Tab/方向键等）与滚轮：M3-1 先记录为"未支持操作"并留痕，不打扰用户
- **双截图捕获**（复用 M1）：每个动作发生时
  - 页面 = 操作点所在窗口（`capture.window_from_point`）→ 复用页面定位与上下文记录；
  - 部件 = 点击点附近的可识别元素：用 `locator` + OCR 反查该点下方/邻近的文字，
    生成与手动"截图目标"**完全同构**的 target（text + rect_in_page + page + nearby）。
- **边录边出脚本**：每块积木即时产出 `schema` 合法的步骤，录完即得可直接运行的 `.sgscript.json`。

**状态：已完成并在真机验证（2026-09-11）**

| 交付 | 位置 | 验证 |
| --- | --- | --- |
| 事件流 → 积木（纯函数） | `engine/recorder.py` | 13 条单测：字符聚合、停顿切分、快捷键不混入输入内容、修饰键不成块、双击合并、滚轮留痕 |
| 录制器骨架（钩子/抓屏/取部件全注入） | `engine/recorder.py` | 11 条单测：含「录到的步骤直接过 schema 校验并写盘」这条验收线 |
| 真机接线（钩子 + 窗口 + OCR 反查） | `engine/recorder_live.py` | 26 条单测 + 真机 e2e 全绿 |
| 真机录制入口 | `engine/scripts/record.py` | 真机 e2e 走通（`smoke/diag/e2e_record.py`） |

真机 e2e 的确定性证据（不依赖合成输入的投递，原因见下）：
录到的目标中心与用户点击点**逐像素一致**（(299,290)）；把该目标矩形从录到的页面图里
裁出来再 OCR，仍读出按钮文字「确定」（64×43 px）——即「录下来的就是用户点的那个东西」。
产出的脚本：`smoke/rec/e2e_recorded.json`（过 `schema.validate`）。

过程中真机暴露并修掉的问题（都已留痕在提交信息里）：
1. **钩子回调里不能抓屏**：底层钩子有超时限制，回调慢会丢用户的输入事件。
   现在回调只记事件，抓帧走后台线程，`stop()` 等队列排空。
2. **页面图必须取自「点击那一刻」的帧**：停止后再抓，页面早已翻页，反查出来的会是错的部件。
3. 停止不用回车（那个回车自己会被录成一块），改用全局热键 `ctrl+alt+q`。
4. 已知限制：中文输入法组合出来的字，钩子只看得到原始按键，会录成拼音字母。

### WP2 录制 UI（Electron 侧）

### WP3 AI 结果语义判定（D3）

- 接口与本地 D2 判定**完全一致**（输入屏幕 → 输出结构化判定），后端换成 glm-4.6v；
- 分辨"成功 / 密码错 / 验证码错 / 断网 / 未知"等失败类型（本地 D2 只能判"预期文字出现没有"）；
- 只在"本地判不出（unknown）"或需要精确区分失败类型时调用（**低频、非实时**，与 M0 结论一致）。

### WP4 运行自校准 AI 化

- M1/M2 的 `calibrator` 已有完整骨架（`SemanticStub` + 重采集 + 自检）；把语义确认换成真 `ZhipuVLM`：
  AI 给归一化建议位置 → **本地圈区精定位**（±100px 内 OCR/模板）→ 重采集页面/部件模板 → 写回脚本；
- **低置信才人工确认**；沿用既有安全兜底（自检不过不写回）。

### WP5 验收与收口

- 录制回放等价性：录一段真实操作 → 回放 → 与手动搭建同一操作的**成功率/误报率**对比；
- AI 语义判定的离线用例集（成功/密码错/断网各若干）→ 准确率记录在案；
- 产出 `docs/M3_收口记录.md` 与验收数据。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 全局钩子干扰用户正常操作 | 录到无关操作 | 录制只在用户点「开始录制」后生效；停止即卸载钩子；UI 明确显示"正在录制" |
| 把输入拆成一字一个积木 | 脚本冗长不可用 | 字符聚合 + 停顿切分（WP1 里做，且有单测钉住） |
| 点击点下方没有可识别文字（纯图形控件） | 部件 target 缺少文字信号 | 退化为"形状模板 + 页面内坐标"（M1 已有这两路），并标注"这块只能靠形状" |
| AI 调用延迟 2–4s | 自校准变慢 | AI 只在首次执行/过程性错误时调用；正常路径零 AI（既定设计） |
| 录制中用户切换窗口 | 页面归属混乱 | 每次动作都按"操作点所在窗口"重新判定页面，切换即视为新页面 |

## 5. 验收口径（M3 DoD）

1. **录制可用**：录一段真实操作（含点击 + 输入 + 停顿）→ 回放成功率 ≥90%、误报率 0。
   → 实测：闭环成立（真人式合成输入录 4 步 → 清空现场 → 无人值守回放 2/2 成功，
   按钮回调触发、输入内容一致、落点与真值逐像素一致）。
   **样本只有 1 个场景放两遍，不足以支撑成功率数字**，跑批留到 M4，本次不虚报。
2. **AI 判定有效**：离线用例集（成功 / 密码错 / 断网 / 验证码错）上，D3 的失败类型判定准确率
   ≥80%（M0 实测 glm-4.6v 语义判定 83%，以此为基线），且**本地判得出时绝不调用云端**。
   → 实测 **92%（11/12）**，含蓄用例 83%；本地优先与"云端不出坐标"都有测试钉住。
3. **自校准可用**：界面改版/失配场景下，AI 确认 + 重采集能恢复定位，且低置信时走人工兜底。
   → 实测：改名场景（前缀也对不上的那种）恢复成功 1/1，写回偏差 7px；
   对照组不接 AI 时正确失败并保留旧值。
4. 三条都要**记录在案**（数据 + 复现命令）。
   → `docs/M2_*` 同规格：`docs/M3_D3验收数据.md`、`docs/M3_自校准验收数据.md`、
   `docs/M3_收口记录.md`；复现命令在各文档与脚本头部。

**最终结论见 `docs/M3_收口记录.md`（含已知限制与三个待用户确认的口径）。**
