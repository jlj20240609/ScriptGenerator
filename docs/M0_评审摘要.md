## 二、关键发现（影响 M1 架构）

1. **OCR rec ~150ms/行**（本机）：整页 OCR 10s+ → M1 部件定位必须“小区域条带/文本索引缓存”；建议引擎默认官方 onnxruntime（比 directml 轮子快 ~2×）
2. **页面模板定位可靠**（web/静态桌面 page 分 0.9–1.0，dev 0–1px）；**低纹理与强动态内容会错位/失效**（tk 旧例 137px、bili 3%）→ M2 融合/局部特征
3. **UWP 在本机呈“渲染幽灵”**（API 置顶成功但屏幕不渲染，calc/set 双目标实证）→ UWP 数据需物理机补测
4. **点击安全闸**（校验不过不点）实测有效：全部轮次零误点用户界面

## 三、判定建议

**GO（首版收敛清单）**
- 首版范围：网页 + 标准控件 + 静态自绘桌面应用（三场景实测 ≥92.5%）
- M1 必须项：解释器 + JSON 脚本模型 + 三级定位引擎 + L1/L2 + 局部 OCR 缓存架构
- 延后项：强动态桌面客户端（bili 型）→ M2；UWP 图标类 → 物理机补测后定；AI 增强 → M3
